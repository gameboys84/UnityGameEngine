# Assembly and directory layout

Shared package sources are maintained in TEngineNi_UPM. UnityProject1 contains project integration, example business rules, scenes, assets and tests. The directory conventions follow the Launcher, Procedure, Hotfix and Editor separation used by TEngineNi.

| Location | Assembly | Responsibility |
| --- | --- | --- |
| com.ni.tengine/Runtime | TEngine.Runtime | Engine modules, resources, scenes, events and timers |
| com.ni.tengine/Editor | TEngine.Editor | Engine authoring and build tools |
| com.ni.gamecore/Runtime/Logic | Ni.GameCore.Logic | Portable networking, server clock, tables, balances and operation timelines |
| com.ni.gamecore/Runtime, excluding nested assemblies | Ni.GameCore | Unity UI, resource ownership, saving and shared components |
| com.ni.gamecore/Editor | Ni.GameCore.Editor | Shared UI generation and authoring tools |
| Assets/Scripts/Launcher and Assets/Scripts/Procedure | Launcher | Startup and native bootstrap; Procedure uses an asmref |
| Assets/Scripts/Hotfix/GameCore | GameCore | Project module facade |
| Assets/Scripts/Hotfix/Runtime/LogicTests | GameRuntime.LogicTests | Portable example business rules and state |
| Assets/Scripts/Hotfix/Runtime, excluding nested assemblies | GameRuntime | Game entry, demo windows and the logic test dashboard |
| Assets/Scripts/Editor | GameProject.Editor | Project asset creation and assembly tooling |
| Assets/Tests/EditMode, PlayMode and Startup | Existing test assemblies | Foundation, resource, lifecycle, startup and UI regression |
| Assets/Tests/Logic and LogicPlayMode | GameLogic.EditModeTests and GameLogic.PlayModeTests | New core, business, transport and assembly checks |

Ni.GameCore.Logic has no engine references. GameRuntime.LogicTests references only Ni.GameCore.Logic and also has no engine references. Runtime UI depends on the model; the model does not depend on the UI. Shared packages do not reference project assemblies. Editor assemblies are restricted to Editor. Test assemblies are not automatically referenced by product code.

Assets/Plugins/Roslyn contains Editor-only compiler dependencies. Their Editor-only PluginImporter settings are versioned in the DLL metadata. Binary dependencies use their own assembly identities rather than an asmdef wrapper.

## Asset ownership

- Assets/Launcher contains bootstrap scenes and resources.
- Assets/AssetBundle contains the demo's YooAsset content.
- Assets/Resources/LogicTests contains small local test rule data.
- Assets/TEngine and Assets/Editor contain project-owned settings and templates.
- Assets/Validation contains reusable test fixtures.
- Packages contains dependency manifests, locks and embedded third-party packages.
- Design contains analysis helpers and reports; it is not a product assembly.

Existing scenes and prefabs retain their GUIDs. New source and directory metadata is generated by Unity. Scripts under Assets must resolve to an explicit assembly; no project source is assigned to a default Assembly-CSharp assembly.

Run `python Design/scripts/verify-assemblies.py` to check ownership, dependency cycles and the portable logic boundaries. Unity assembly tests additionally check compiled references and plugin compatibility.
