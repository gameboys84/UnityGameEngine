## 当前结构与问题

现有实现是 TEngine 内嵌的 I2 风格本地化核心，加上 fork 的 CSV/YooAsset 桥接、Luban 文本表和 RTLTMPro 扩展。下述问题针对当前集成实现，不应泛化为所有 I2 版本的问题。

1. 文本有两条链路：Launcher/组件使用 LanguageSource、CSV、Localize/ScriptLocalization；业务 StringManager 使用 Luban TbLocConfig。StringManager 依赖语言枚举到 LocLanguage 的转换，再按数组下标取文本。语言状态共用，但数据与刷新方式不同。
2. [SetLanguage](E:/Git/TEngineNi/UnityProject/Assets/TEngine/Runtime/Module/LocalizationModule/LocalizationManager.cs:244) 返回 bool；尚未加载的语言调用 LoadLanguage(...).Forget() 后立即返回 true。调用方无法等待加载成功，失败也无法作为切换结果返回，连续选择语言还需处理旧请求晚完成的问题。
3. 同一文件的 LoadLanguageTotalAsset/LoadLanguage 使用 LoadAssetAsync<TextAsset>，解析后未见配对 UnloadAsset。加载资源的生命周期需要核验，不能因解析成字符串就认定资源自动释放。
4. [LoadFromBundle](E:/Git/TEngineNi/UnityProject/Assets/TEngine/Runtime/Module/LocalizationModule/LocalizationManager.cs:305) 使用同步 LoadAsset。字体、图片的 Target 通过翻译对象查找，与统一异步资源加载和取消的诉求不匹配。
5. TMP Target 使用 SecondaryTerm 查找字体/材质。这增加了文本 Term、字体 Term、资源地址、语言文件等配置关系，难以直观看出窗口实际依赖。
6. I2 组件、TEngine GameEvent、StringManager 转发事件共同参与刷新，业务 UI 还要手工刷新动态文本。应避免同一属性被 Localize 和业务代码同时控制。

网络现状补充：Fantasy 已从 manifest 移除；协议文件已删除，原网络实现被条件编译包裹，GameApp/GameModule 调用已调整。属于用户进行中的改动，不恢复这些删除。本次没有验证编译，不宣称已经完全清理所有依赖。

## 路线比较

| 路线 | 优点 | 成本与适用条件 |
|---|---|---|
| 保留 I2 核心，收敛 TEngine 接口 | 迁移较小，保留已有组件与数据 | 仍需改造资源桥接、切换等待、引用释放和双文本链路；旧复杂度会部分保留 |
| Unity Localization | 成熟的 String/Asset Table、自动更新事件、Smart Strings 与编辑器工作流 | 默认资源集成基于 Addressables；采用 YooAsset 时需评估自定义 provider/数据库或双资源体系，不能当直接替换 |
| Luban + YooAsset + TMP，加薄的本地化适配层 | 复用当前工具链和框架；文本、字体、图片使用一个资源入口；对中英文范围较清晰 | 要维护 UI 绑定、导出校验与切换状态机；以后复数、翻译协作等需求增加时需引入成熟能力 |

建议先验证第三条路线。复用既有模块，仅替换本地化集成与 UI 绑定层；并非从零搭建整个框架。若项目更重视成熟翻译编辑器、复杂语言规则及团队协作，则重新评估 Unity Localization 的适配成本。

官方依据：[Unity Localization Addressables 集成](https://docs.unity3d.com/Packages/com.unity.localization@1.5/manual/Addressables.html)、[LocalizedString/LocalizedAsset 事件和脚本 API](https://docs.unity3d.com/Packages/com.unity.localization@1.5/manual/Scripting.html)、[I2 资源桥接说明](https://inter-illusion.com/assets/I2LocalizationManual/AssetsTab.html)。本轮未制作任何替换原型，不宣称兼容性已经通过。

## 建议的实现边界

### 数据

- 用稳定 key 与 locale code（zh-CN、en）组织数据，不依赖语言枚举的数组位置。
- 编辑源可继续使用 Excel/Luban，但所有文本同一来源。首包和业务是不同分组/导出产物，不是两套翻译数据。
- 首包含启动、下载、失败提示所需的中英文与基础字体，确保没有网络和热更代码时也能显示界面。
- 业务表可由 YooAsset 加载。初期文字量小时两语言一起预载；字体和语言专用图片根据实际内存需求分开，避免过早复杂分包。
- 图片表映射资源 key 到 locale 地址。只有存在差异的图片填写语言覆盖，通用图片走 shared fallback。

### 语言切换

拟议入口为 SwitchLanguageAsync(locale, cancellationToken)，返回明确成功/失败结果；这是设计提案，当前工程没有此 API。

流程：校验目标 → 准备文本与必要字体 → 确认请求仍有效 → 提交当前语言 → 通知绑定更新 → 持久化偏好。准备失败保留原语言。连续请求使用序号或串行策略，防止旧请求覆盖新语言；取消路径仍须释放已获得资源。

可见 UI 需要的专用图片可以在窗口侧异步更新，新的图片未就绪时保留旧图或占位图。切换接口必须说明其完成范围：全局文本与字体就绪，不代表所有尚未打开的窗口资源均已预载。

### 字体

- 使用 font profile（正文、标题、数字等），由 locale 选择 profile；避免每条文本都配置一个字体翻译 Term。
- 首阶段可以比较“共享中英文 TMP 字体”和“拉丁字体 + 中文 fallback”，依据字形覆盖、材质和内存实测选择。
- 从静态翻译内容导出字集，另覆盖格式化参数、数字、玩家名等动态文本。需检查缺字而非仅检查字体地址存在。
- 活跃 UI 和 TMP fallback/material 尚在引用时，不释放旧字体。字体资源通过统一 YooAsset 生命周期管理。

### UI

- 薄绑定组件负责 key、格式化参数、font profile，以及图片 asset key。
- 动态文本通过同一服务取词/格式化；已预载文本查询同步，资源准备和切换异步，避免每帧/每次取词都发起加载。
- 绑定组件在激活时订阅与刷新，失活时取消进行中的 UI 请求，销毁时解除监听和释放资源。隐藏窗口重新显示时读取当前语言版本。
- 保留请求版本与销毁检查，避免已经关闭或复用的窗口被旧图片请求改写。
- 首阶段不引入阿拉伯语排版和 RTL 配置；保留将来扩展边界，已有 RTLTMPro 是否移除另行评估。
