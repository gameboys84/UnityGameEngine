# 工程与版本管理约定

整理日期：2026-10-26。

## 入库范围

| 内容 | 规则与原因 |
| --- | --- |
| Assets 全部有效输入及 .meta | 包含源码、场景、Prefab、材质、插件 DLL、测试、验证资产和编辑器模板；运行时地址加载和工具输入不能仅靠静态场景引用删减 |
| Packages | 管理 manifest、packages-lock 和三个第三方本地包；Ni 两个包的源码由 Ni/FrameworkPackages 管理，当前仅保存依赖引用 |
| ProjectSettings | 保留共享设置，包括版本、构建场景、Visible Meta Files 与 Force Text；UserSettings 是本机设置 |
| 根目录规则 | README、AGENTS、.gitignore、.gitattributes；换行策略由 .gitattributes 管理 |
| Doc | 六份核心说明，以 README 为入口；功能结论、使用方法和来源各有明确归属 |
| Design/notes | 五份历史分析及本轮包化任务，保留日期、来源、决策与验证状态 |
| Design/scripts | 来源导入记录脚本、只读差异审计、本地 MCP 辅助调用、仓库检查脚本 |

测试所需的 256 个文本资源、独立窗口、模板和夹具属于工程输入，应入库。Roslyn DLL 为现有工具依赖，随源码保留。没有单个超过 100 MiB 的当前入库文件，本轮不引入 Git LFS 或子模块。

## 忽略范围

- Unity 的 Library、Temp、obj、Logs、UserSettings、IDE 工程、构建输出、Bundles、ServerData、HybridCLR 安装/中间产物。
- YooAsset 构建复制到 `Assets/StreamingAssets/yoo` 的内置包输出；离线 Player 构建前必须从源码构建资源并按当前构建流程复制，不能把“克隆后 Editor 可运行”等同于离线安装包已具备内置资源。
- 本机 `.vscode`、`.idea`、`.vs`、AI 会话设置、MCP session、一次性备份、截图、日志、Console 回执和中间测试输出。
- `Design/reports/` 整体忽略，来源清单、差异补丁、审计快照和历史测试结果均不入库。需要时重新审计或运行测试，重要结论写入核心文档，不用 `git add -f` 强制加入报告。

忽略项保留本机，不清空活动缓存。根 .gitignore 管理 IDE/OS/AI 本机文件和 Design 产物；UnityProject1/.gitignore 自主管理 Library、Temp、构建、IDE 工程及 Unity 测试临时场景等 Unity 专有规则。根规则不直接指定 UnityProject1 缓存或构建路径。

## 文档维护

已确定的事实和约定更新到 Doc；新候选、研究、未决定的建议留在 Design/notes。实施时的反复尝试不单独积累为核心文档，稳定的使用方式和重要故障原因合并到对应指南。

测试结果在 reports 本机生成。核对实际结果后，将日期、环境、覆盖范围和结论更新到核心文档。现有 `baseline-20261012` 仅是本机历史记录，不入库；重跑会产生新的结果，不能原样还原历史运行、导入时源哈希或已删除资源的明细。

TEngineNi 差异与补丁需要时运行 `Design/scripts/audit-tengine-changes.ps1` 生成，依赖可访问的来源工程；reports 及其时间戳快照均不入库。审计现改为共享包身份/引用和 Ni 工作树变更记录；后续新改动仍需决定保留范围，来源与状态详见修改台账。

## 审阅与检查

本仓库保留 UnityGameEngine 远端初始 LICENSE 历史，并按用户 2026-10-27 的授权提交与推送必要工程内容。检查暂存范围：

```powershell
git diff --cached --stat
git diff --cached -- Doc README.md .gitignore .gitattributes
py -3 Design/scripts/verify-repository.py
```

检查脚本验证 Git 范围、忽略策略、Assets 元数据配对和本地包输入，不依赖 reports 存在；输出属于仓库结构检查，不代替 Unity 编译/运行测试。后续包化已修改共用源码位置与依赖，并完成当前 Editor 的 3/3 EditMode、10/10 PlayMode 和完整 .NET 构建。Ni 独立 Editor 验证仍待执行。


共用源码的唯一权威位置是独立 TEngineNi_UPM 仓库，Ni/FrameworkPackages 是固定提交的子模块。本机开发引用可能包含未提交改动；Git 稳定消费使用已推送的完整提交。切换工具与前置条件见《TEngine引入方式与来源》。
