# 当前框架整体功能说明

更新及包化回归：2026-10-26；原功能盘点基线：2026-10-12。以 `MyUnityFramework/UnityProject1` 的实际代码、依赖和验证记录为准；不把上游框架宣传能力直接等同于本工程已完成能力。

## 1. 当前定位

当前工程是基于 TEngineNi 的 Unity 客户端运行底座，已经能在 Editor 中完成启动、资源初始化、进入主场景，并通过界面验证部分共用接口。它适合继续承载单机题材原型，尚未完成对外用户测试所需的数据采集、设备发布和产品保障链路，也没有 SLG 业务模型或联网同步实现。

| 基础项 | 当前状态 |
| --- | --- |
| Unity | 2022.3.62f2 |
| UniTask | 本地包 2.5.11 |
| YooAsset | 本地包 2.3.17 |
| HybridCLR | 本地包 8.8.0；安装包存在，代码热更新运行链路未验收 |
| 主框架 | TEngineNi 维护的 com.ni.tengine 0.6.0 与 com.ni.gamecore 0.1.0，共用源码已独立发布到 TEngineNi_UPM，当前使用完整 Git SHA 引用 |
| 平台验证 | Windows Editor；移动端/小游戏未完成独立验收 |
| 网络 | 当前没有游戏网络实现；Fantasy 未迁入，TouchSocket 尚未接入 |
| 游戏内容 | 主场景和专项测试 Demo；未迁入 DeadEmpire 玩法 |

## 2. 模块与程序集

| 层 | 目录 | 职责 |
| --- | --- | --- |
| 主包启动 | Scripts/Launcher、Scripts/Procedure | RootModule/GameEntry 生命周期、加载界面、启动状态机、资源包初始化、反射调用游戏入口 |
| TEngine 核心 | Packages/com.ni.tengine/Runtime | 模块管理、事件、日志、时间、FSM、计时、资源、场景、对象池、音频、调试、多语言已有实现 |

| 项目门面 | Scripts/Hotfix/GameCore | 原 GameCore 程序集保留 GameModule，引用 Ni.GameCore；Ni 自身保留其入口/网络/配置门面 |
| 游戏层 | Scripts/Hotfix/Runtime | GameApp、MainSceneView、专项测试 UIWindow；后续承载各 Demo 的业务 |
| 原生启动资源 | Assets/Launcher | 启动场景、启动器预制体、配置；资源包不可用时仍可显示错误和重试 |

## 4. 验证证据

2026-10-26 包化后 PlayMode 联合测试 10/10 通过（约 35.79 秒）：既有基础/启动/专项测试、独立 SLG UI 与批量工作负载，以及模块关闭后消费者晚释放/下一会话重建。覆盖 100,000 条固定行高虚拟列表、模态遮挡、邮件防重复、本地聊天、1,000 个 UI 行与 3D 实例的直接/池化操作、256 个不同资源及飘字回收。失败重试用例使用临时配置并独立断言预期错误，避免污染日常 Console。专项界面检查包含输入模块模拟按下/抬起；不等同于实际桌面硬件鼠标验收或移动设备性能结论。

同轮 EditMode 基础测试 3/3 通过：优先队列、循环集合、存档往返和路径校验。26 个 Prefab 无缺失脚本，完整 .NET 解决方案构建 0 错误。Ni 自身只完成主程序集的 .NET 集成检查，缺 CLI/Pipeline，尚无独立 Editor 验证。

本轮原始结果在本机 `package-playmode-results.json`、`package-editmode-results.json` 与 `package-unity-final-check.json`（均位于 Design/reports）；运行方式和修正摘要见《测试与演示指南》。原始结果、Console 回执和截图仅保存在本机被忽略的 `Design/reports/`，仓库不依赖这些文件；需要时运行测试获得新的验证结果。Editor 模拟成功不代表设备性能、离线安装包、远端下载、代码热更或公开发行已经完成。

## 6. 当前具体改进点

1. 存档直接 FileMode.Create 覆盖文件；中断/取消可能留下部分数据，需补写入队列、临时文件替换、备份和迁移。
2. 存档加载缺失文件返回 default；调用方需区分首次启动、缺失、损坏和版本不兼容。当前 Demo 直接读字段时可能只显示一般异常。
3. 可选存档加密沿用硬编码的旧 AES 参数；适用性和密钥策略未定，不应视为防作弊或敏感信息存储方案。
4. 现有 GameTime/Timer 基于 Unity 运行时间，需另建持久任务与离线时间语义，才能支撑放置和 SLG 队列。
5. 诊断面板已有不少即时信息，但尚未形成可关联到 app/config/题材/会话版本的历史数据。
6. 配置表和业务模型缺位；如果直接把经济/队列写在 MonoBehaviour/UIWindow 中，后期联网会扩大迁移成本。
7. 仍需统一约定操作取消、并发去重、超时、错误码、资源持有者和关闭顺序。
8. 依赖/构建需固定来源与适配记录；MCP 使用 main 引用，继承工具含上游路径约定，发布前需整理可复现构建。

后续修改建议属于待讨论方案，另存于 Design，不在本说明中当作已经实现或已选定模块。


## 7. 已确认目标与开发边界

- 面向 Unity 客户端，优先移动平台，兼顾 2D/3D，后续考虑小游戏；用途是学习研究、个人长期复用和小团队开发。
- 早期重点是单机玩法验证和用户数据收集，后续希望便于扩展为 SLG。具体题材、采集供应商、网络方案和多语言最终方案尚未决定。
- DeadEmpire-DEV 是基础能力迁移和验证参考，业务逻辑暂不纳入通用层。不恢复或覆盖来源工程现有改动。
- 一个核心职责保留统一入口：资源和场景沿用 TEngine/YooAsset，UI 沿用 GameCore。旧工程的资源、事件和全局 UI 管理器不整套并入。
- GameCore 不引用 GameRuntime、游戏表或服务器协议；题材模型、假数据、Demo/UI 资产归 GameRuntime。新增共用能力按《TEngineNi修改台账》记录决定；本轮已授权合并的源码由 Ni 包统一维护，后续新范围仍需确认。
- `.meta`、GUID 和旧 Prefab 的序列化字段属于兼容契约。脚本可编译不代表旧资产复制后可运行。

## 8. 共用接口的使用约定

- `ResourceReference.LoadAsync` 返回 AssetLease，使用完 Dispose；`LoadGameObjectAsync` 的实例销毁触发框架引用释放。初始化资源包后才能加载。
- `ShowUIAsyncAwait` 等待窗口准备完成；取消单个等待不关闭其他调用者共享的窗口，关闭窗口会终止其加载。
- LoopScroll 单元采用预载 Prefab 和列表局部回收；清理实例后才释放源资源。VirtualizedScrollList 暂限固定行高竖向列表。
- `CircleList.GetData` 返回时间顺序副本，不暴露内部数组。LocalSave 的原生目录是 `persistentDataPath/LocalSave`。

```csharp
using GameCore;

var window = await GameModule.UI.ShowUIAsyncAwait<ExampleWindow>(cancellationToken);
var instance = await GameModule.Resource.LoadGameObjectAsync("prefab-location", parent, cancellationToken);
using (var lease = await new ResourceReference("text-location").LoadAsync<UnityEngine.TextAsset>(cancellationToken))
{
    var text = lease.Asset.text;
}
await GameModule.LocalSave.SaveAsync("state.json", saveData, cancellationToken: cancellationToken);
```

示例窗口、地址和数据由调用方提供。原 FoundationBootstrap 已退役；统一入口为 Launcher，隔离夹具保留在 `Assets/Validation/Foundation`，准备菜单为 `TEngine/Validation/Prepare Foundation Assets`。


## 9. 共用包维护

两边使用的 com.ni.tengine / com.ni.gamecore 由独立 TEngineNi_UPM 仓库维护；Ni/FrameworkPackages 子模块固定其提交，当前消费工程通过远端 Git 固定同一 SHA。原目录迁移、程序集、项目配置边界、稳定 Git 引用和 IL2CPP/AOT 限制详见《TEngine引入方式与来源》。不复制包源码回 Assets；项目 Settings 与生成结果继续保存在 Assets。
